## Mudou de rumo

**`frontend/Dockerfile` migrou de `[agent]` para `[subagent]`.** `create-next-app` recusa diretório não vazio, então o arquivo só podia existir depois do scaffolding. Ordem de execução, não mudança de critério.

**`BACKEND_INTERNAL_URL` passou a ser build-arg além de env de runtime.** O subagent descobriu executando: o Next congela os rewrites no `routes-manifest.json` durante o build, então a variável em runtime não alcançava o proxy. Correção dele estava certa, mas criou fonte dupla de verdade — o `.env` seguia documentando a variável, o server component a lia em runtime, e o rewrite usava o default do Dockerfile. O agent fechou passando a **mesma** variável por `build.args` e `environment`.

## Quebrou

**Healthcheck do frontend eterno em `starting`.** No Alpine `localhost` resolve `::1` primeiro e o Next escuta só IPv4. Corrigido para `127.0.0.1`. O healthcheck do backend não sofria (JVM faz dual-stack), mas foi normalizado também — duas regras diferentes na mesma stack é armadilha adiada.

### Nota sobre o teste de cache

A primeira tentativa usou `touch` no `.java` e deu `CACHED` em tudo — inconclusiva, porque o Docker faz hash de **conteúdo**, não de mtime. Refeito com alteração real: `RUN mvn dependency:go-offline` ficou `CACHED` e só `COPY src` em diante reconstruiu. É o comportamento correto.
