# Domínio

```
                    Pedido
                      │
                      ^
Cartorio ──< CartorioDocumento >── Documento
    │                                  │
    └──────────< Agendamento >─────────┘
```

- **Pedido** agrega N agendamentos e carrega o cabeçalho da tela (lead, observação, status, autor, data).
- **Cartório** tem um nome e um endereço, e emite N documentos.
- **Documento** tem apenas um nome, e pode ser emitido por N cartórios.
- **Agendamento** amarra `pedido + cartorio + documento + requerente`. Nasce `PENDENTE`. É o "documento solicitado" do layout.

## Tabelas

**cartorio** — `id`, `nome`, `cep`, `rua`, `numero`, `complemento?`, `bairro?`, `cidade`, `uf`, `created_at`, `updated_at`

**documento** — `id`, `nome` (único, case-insensitive), `created_at`, `updated_at`

**cartorio_documento** — `cartorio_id`, `documento_id` · PK composta · FK `ON DELETE CASCADE`

**pedido** — `id`, `numero` (sequencial, único — renderiza "Pedido #1"), `lead`, `observacao?`, `status` (`EM_ANDAMENTO`/`CONCLUIDO`/`CANCELADO`), `criado_por`, `created_at`, `updated_at`

**agendamento** — `id`, `pedido_id`, `cartorio_id`, `documento_id`, `tipo_pessoa` (`FISICA`/`JURIDICA`), `nome_razao_social`, `documento_identificacao`, `data_nascimento?`, `status` (`PENDENTE`/`EM_ANDAMENTO`/`CONCLUIDO`/`CANCELADO`), `created_at`

## Regras que o código precisa garantir

1. **Par válido.** O `(cartorio_id, documento_id)` de um agendamento tem que existir em `cartorio_documento`. Violação → `409`. É o que alimenta o combo condicional do front. **Regra de serviço**, não de constraint — o banco não consegue expressar isso sem trigger, e trigger aqui não paga o preço.
2. **Dado sensível sem máscara.** CPF/CNPJ chega mascarado, é normalizado para dígitos na entrada da API, validado por dígito verificador e persistido cru. Máscara é responsabilidade da apresentação, e de mais ninguém.
3. **`tipo_pessoa` decide o formato.** `FISICA` → CPF, 11 dígitos. `JURIDICA` → CNPJ, **12 caracteres `[A-Z0-9]` + 2 dígitos verificadores**. Incoerência → `400`. Garantido **também** no banco por `CHECK` combinado — defesa em profundidade, porque é a regra que protege dado pessoal.

   > **CNPJ é alfanumérico** desde a IN RFB 2.229/2024. A aritmética do dígito verificador não mudou: o valor de cada caractere é o ASCII menos 48, então `'0'..'9'` valem 0..9 e `'A'..'Z'` valem 17..42 — CNPJ todo numérico é o caso particular sem letras. O que **muda de verdade é a desmascaração**: `replaceAll("\\D","")` apaga as letras e transforma documento válido em lixo silenciosamente. Usar `Documentos.normalizarIdentificacao`, que remove só a máscara e sobe para maiúsculas.
4. **Data de nascimento é de pessoa física.** `data_nascimento` só pode ser preenchida quando `tipo_pessoa = 'FISICA'`. `CHECK` no banco.
5. **Status inicial fixo.** Agendamento nasce `PENDENTE`; mudança só via `PATCH /status`.
6. **Documento paginado.** `GET /documentos` default `size=10` — requisito explícito da diretriz.
7. **Nome de documento é único sem diferenciar caixa.** Índice único em `lower(nome)`, não `UNIQUE` simples.

## Convenções de schema

- **IDs**: `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- **Tempo**: `TIMESTAMPTZ`, mapeado para `Instant`. Nunca `TIMESTAMP` sem fuso.
- **Enums**: `VARCHAR` + `CHECK`, não enum nativo do Postgres. Casa com `@Enumerated(STRING)` e não exige `ALTER TYPE` para acrescentar valor.
- **`pedido.numero`**: `DEFAULT nextval(...)` de sequence dedicada. Nunca `count()+1`.

## Semântica de exclusão

| Apagar | Efeito |
|---|---|
| `pedido` | `CASCADE` nos agendamentos — o pedido é o dono deles |
| `cartorio` / `documento` com agendamento | `RESTRICT` → serviço devolve `409` explicando |
| `cartorio` / `documento` sem agendamento | Remove, com `CASCADE` só no vínculo `cartorio_documento` |

O vínculo N:N é acessório: some junto. O agendamento é fato histórico: segura a exclusão.
